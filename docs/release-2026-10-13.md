# Local release update · 2026-10-13

This update reconciles the release with the local pipeline and uses **RidgePFM**
as the method name for new runs.

- New RidgePFM outputs use `PFM/RidgePFM/` and `RidgePFM_*` filenames. Default
  weights are FC **1.0** and spatial prior **0.05**. Explicit study settings win;
  existing outputs are not renamed or recomputed.
- The final TANS module is retained and its example YAML uses RidgePFM inputs.
  The wrapper can locate an existing `RidgeFusion` folder when `RidgePFM` is
  absent; the study YAML must name the corresponding legacy files.
- First-party pipeline scripts, QC helpers, and regression tests are reconciled
  with the local checkout, retaining the release's extra metadata regression test.
- Local raw-R² NSI diagnostics are merged into the release's newer pfm-nsi copy,
  preserving its median-based usability exports and CLI improvements. The release
  pins the updated pfm-nsi submodule commit containing these diagnostics.
- The raw-import template, optional Infomap comparison helper, and container
  launch recipes are included. A missing container configuration is supplied and
  the container instructions no longer reference a nonexistent smoke-test script.
- The shorter README introduces individual-focused fMRI, repeat sampling, PFM,
  and TANS. The detailed SIMD01 gallery remains available with its provenance.

The public study template retains portable paths and explicit optional-tool
settings. Study-specific configurations, credentials, experimental prior sets,
participant-derived classifier training data, and optional NORDIC source are
not copied into the release. NORDIC must be installed separately under its license.
TANS and its calibration resources remain in the separate pfm-tans installation.

Validation covers unit tests, module routing with stub scientific tools, local
documentation links, gallery integrity, and browser layout. It does not rerun
participant processing, build a container image, or run TANS simulations.
Study configuration templates now resolve repository resources when copied out
of the checkout. Acquisition counts, scanner patterns, and TANS hardware must be
configured by the user. PFM and TANS are opt-in; experimental multi-network
analysis is disabled by default. See [configuration setup](configuration.md)
and [dependencies](dependencies.md).
