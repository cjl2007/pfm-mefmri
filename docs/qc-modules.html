QC Modules

The output gallery includes actual coregistration, distortion-correction, motion, NSI, and seed-FC examples. Figure slots below are suggested report families; only the explicitly linked gallery assets are bundled.

The pipeline includes multiple QC layers. They are intended to answer different questions: whether inputs were understood, whether anatomy and field maps line up, whether motion remains coupled to signal, whether ME-ICA component decisions look plausible, whether the data support PFM, and whether final network maps are stable enough to interpret.

The functional QC root is controlled by:

QC_OUTPUT_DIRNAME="QC"

Most QC outputs therefore live under:

func/<FUNC_DIRNAME>/QC/

Input Validation

Enable with:

QC_VALIDATION_ENABLE=1

Use this first when onboarding a new dataset. It checks that the expected task, session, run, echo, SBRef, JSON, and fieldmap inputs are visible before the heavier stages begin.

Expected location:

func/<FUNC_DIRNAME>/QC/Validation/

Motion Grayplots And QC-FC Proxy

Enable with:

MOTION_GRAYPLOTS_QC_ENABLE=1
MOTION_GRAYPLOTS_QC_STRICT=0
MOTION_GRAYPLOTS_QC_FD_THRESHOLD=0.3

Primary report:

func/<FUNC_DIRNAME>/QC/MotionGrayPlots/motion_grayplots_qc.html

Important files:

MotionGrayPlots/reportlets/subj_desc-motionGrayplots_stacked.png
MotionGrayPlots/reportlets/subj_desc-motionCouplingSummary.png
MotionGrayPlots/reportlets/subj_desc-motionGrayplot_S<session>_R<run>.png
MotionGrayPlots/motion_grayplot_metrics.tsv
MotionGrayPlots/manifest.json

The report stacks multiple processing stages and overlays motion, FD, DVARS, FD censor markers, and run boundaries. When Siemens RESP/PULS logs and their acquisition-info log are present under physio/unprocessed/<func>/session_<N>/run_<N>/, it also aligns respiratory and pulse traces to scanner acquisition ticks and displays them above FD. Missing physiology remains optional and does not prevent report generation. The coupling summary reports motion/signal relationships before and after censoring.

FD uses the same historical calculation as CIFTI concatenation: motion parameters are bandstop-filtered only for TR < 2 seconds, from 0.2 Hz to Nyquist minus 0.019 Hz. Frames at or above the threshold are censored. Set MOTION_GRAYPLOTS_QC_FD_THRESHOLD equal to CONCAT_FD_THRESHOLD for matching retained-frame counts. Invalid or too-short motion inputs fail explicitly instead of silently switching to unfiltered FD.

Review priorities:

  • Look for run-specific signal disruptions.
  • Compare pre-denoising and post-denoising stages.
  • Check whether high-motion frames dominate DVARS or grayordinate structure.
  • Inspect median_abs_grayordinate_fd_r and p95_abs_grayordinate_fd_r in the metrics TSV for residual motion coupling.

NSI_ENABLE=1
NSI_USE_EXTERNAL_CLI=1
NSI_USABILITY_MODEL=1

Crawling Seed FC Movie

Enable with:

CRAWLING_SEED_FC_ENABLE=1

This selected-dataset stage runs after pfm_prepare and before NSI when enabled. To prepare/reuse the selected dataset and generate its movie, use:

START_FROM_MODULE="pfm_prepare"
STOP_AFTER_MODULE="crawling_seed_fc"

Primary output:

pfm/QC/CrawlingSeedFC/sub-<Subject>.mp4

The module builds a dense correlation CIFTI and renders a Workbench/wb_surfer2 movie from sampled seed vertices. It is intentionally resource-heavy. The dense correlation intermediate can be tens of GB and is deleted by default unless:

CRAWLING_SEED_FC_KEEP_DCONN=1

Use this movie to look for broad spatial artifacts, poor surface alignment, unusual connectivity structure, or session/run patterns that are hard to see in static plots.

Selected PFM dataset QC

The downstream order is concat (per task) → pfm_prepare (selected dataset) → crawling_seed_fc → nsi → pfm → tans. This relocation concerns downstream dataset NSI. Component-level NSI used during ME-ICA reclassification remains run-specific.

NSI and seed-FC movies are optional stages independent of PFM_ENABLE; the selection in PFM_INPUT_TASKS still determines their dataset when mapping is off.

For combined rest and task mapping, set the selected tasks explicitly. Both QC modules receive the exact censored CIFTI in PFMPrepSummary.json (or the explicit PFM_INPUT_CIFTI override); no per-task fallback is used. NSI's model duration is computed from retained input frames × CIFTI TR in seconds, not the acquired frame count in a single task's metadata. External CIFTIs therefore do not require an unrelated ScanInfo.json to determine duration. Task/run provenance remains in dataset.json and the concatenation metadata; external overrides retain their explicit unverified-task-membership designation.

PFM_INPUT_TASKS=("rest" "Motor" "WorkingMemory")
START_FROM_MODULE="pfm_prepare"
STOP_AFTER_MODULE="nsi"

This prepares/reuses selected inputs and runs the enabled dataset QC without rerunning functional preprocessing or mapping. Starting at crawling_seed_fc or nsi verifies/reuses preparation. Starting at pfm skips the earlier QC stages; starting at tans retains its mapping-only resume behavior. Changed input selection is rejected on resume; restart from concat to rebuild, or choose a separate PFM_OUTDIR to retain both analyses. STOP_AFTER_MODULE="concat" produces per-task concatenations only; it no longer runs movies as a sub-step.

Receipts pfm/QC/nsi_dataset.json and pfm/QC/crawling_seed_fc_dataset.json bind the input CIFTI, dataset fingerprint, QC settings, code/resources and output signatures. Matching complete outputs are reused; missing or changed outputs are regenerated. Set PFM_QC_FORCE=1 to force QC regeneration. The pipeline routes these QC outputs to <PFM_OUTDIR>/QC/ and does not move historical func/<task>/QC/NSI or func/<task>/QC/CrawlingSeedFC directories. Low-level standalone shell calls retain their legacy defaults and support explicit input and output arguments via environment variables.

Network-colored grayplots

After network mapping, grayplots are updated in place at:

func/<task>/QC/MotionGrayPlots/motion_grayplots_qc.html

The same reports show motion, physiology, and network-colored grayplots. Cortex and subcortex are grouped by network separately, with a thin divider. Both blocks use assignments from the same fitted dlabel; cortical-only exports leave subcortex unassigned. Early QC can run before mapping; fitted network labels replace the initial row order when available. Subsequent QC reuses those labels. No second report set or hash-named output folder is created.

<PFM_OUTDIR>/QC/MotionGrayPlots.html links to these reports. PFM_NETWORK_GRAYPLOTS_ENABLE=1 enables the update; PFM_NETWORK_GRAYPLOTS_LABEL optionally selects a fitted dlabel. Successfully replaced legacy hash folders are removed; unsuccessful updates preserve the existing report.
