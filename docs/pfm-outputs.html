PFM Outputs

See example maps and continuous representations. Network labels and weights can feed the optional TANS module after QC and explicit selection of the input maps and metadata.

Choose rest-only or rest plus selected tasks

PFM input selection is separate from which functional tasks the pipeline processes. Use the task directory names configured in FUNC_DIRNAME:

# Rest only
PFM_INPUT_TASKS=("rest")

# Rest plus selected tasks (example names; these tasks must exist)
PFM_INPUT_TASKS=("rest" "Motor" "WorkingMemory")

The selected runs are prepared together for a single subject-level PFM analysis. The pipeline applies the configured per-run demeaning, variance normalization, and FD censoring, retaining task/session/run membership in the preparation metadata. Unselected tasks can still be processed without contributing to PFM. Task selection alone does not remove task-evoked responses; combining task data changes the data supporting the map and should be documented.

Outputs are organized under pfm/ at the subject root. Inspect pfm/dataset.json and the preparation summary to verify the selected inputs and retained duration. An explicit PFM_INPUT_CIFTI overrides automatic input construction; its task membership is not verified by this selection list. See dataset organization for the complete directory layout.

FD follows the historical concatenate_scans.m calculation independently for each run. For TR < 2 seconds, the six motion parameters receive a zero-phase, 10th-order Butterworth bandstop from 0.2 Hz to Nyquist minus 0.019 Hz before FD is calculated. Runs with TR >= 2 seconds use unfiltered motion. FD uses round(2.5 / TR) backward differences with MATLAB's rounding, a 50 mm rotation radius, and zero FD for the leading lag frames of each run. Censoring retains frames with FD < CONCAT_FD_THRESHOLD (default 0.3 mm).

The Python filter uses second-order sections for numerical stability and MATLAB-compatible edge padding. This preserves the historical filter design; it does not reproduce numerical artifacts of the old direct-form filter, which can be unstable near TR = 2 seconds. Filtering requires more than 60 frames per run when TR < 2 seconds and fails explicitly for shorter runs. This filtering applies to motion parameters, not the BOLD signal.

FD.txt stores the FD used for censoring at full precision. ScanInfo.json records each run's TR, filter settings, and lag, and PFMPrepSummary.json records the FD method. Motion grayplot QC uses the same calculation; keep its threshold equal to CONCAT_FD_THRESHOLD to compare retained-frame counts.

Existing derivatives are not changed by updating the code. To adopt this FD calculation for an already processed subject, regenerate concatenation and the downstream analyses that consume its censored CIFTI, and refresh motion QC.

func/<FUNC_DIRNAME>/PFM/

Set PFM_STRATEGY="all" to run both RidgePFM and Infomap in one PFM stage. Each strategy writes to its own subfolder under PFM/.

RidgePFM

Taxonomies, WTA, softmax, and volume maps

PFM_RF_TAXONOMY="Lynch2024"  # Lynch2024 | Du2024 | Hermosillo2024 | Kong2019
PFM_PRIORS_MAT=""            # empty: use the selected bundled taxonomy
PFM_SUBCORT_PRIORS_NII=""
PFM_RF_VOLUME_ENABLE=1       # optional; default 0
PFM_RF_VOLUME_ANATOMICAL_TARGET="acpc" # acpc | native | custom
PFM_RF_VOLUME_REFERENCE=""  # target grid; native defaults to anat/T1w/T1w.nii.gz
PFM_RF_VOLUME_ACPC_TO_TARGET_XFM="" # native auto-selects xfms/acpc2orig.mat

Ribbon mapping always occurs in the subject's ACPC anatomical space, where the white and pial surfaces are defined. The native target then applies the saved ACPC-to-original transform and writes on the original T1w.nii.gz grid. A custom target requires both PFM_RF_VOLUME_REFERENCE and PFM_RF_VOLUME_ACPC_TO_TARGET_XFM. WTA output is a Workbench label volume with the taxonomy names and colors embedded; continuous-score outputs remain scalar 4D NIfTI files.

The four prior sets live in res0urces/PriorsPFM/<taxonomy>. Lynch2024 and Hermosillo2024 supply cortical and subcortical spatial priors; Du2024 and Kong2019 supply cortical priors only. Targets without spatial support use FC alone: no other taxonomy's subcortical labels are substituted. The availability map identifies informative spatial-prior rows. Custom cortical priors override the taxonomy selection. To add subcortical spatial support with custom priors, supply an explicitly matching custom volume prior; otherwise volume assignments use FC. Use a different PFM_OUTDIR for each taxonomy when retaining multiple analyses.

Full-data winner-take-all labels identify the network with the largest fused score. _FusedScoreSoftmax.dtseries.nii contains a continuous weight for every network at each location. These softmax weights summarize competition among the fitted network scores; they are not calibrated probabilities of biological identity. _TopFusedScoreWeight.dtseries.nii records the weight of the winning label.

Volume export writes WTA labels and fused-score softmax weights under Volume/. Workbench maps cortex using the subject's midthickness, white, and pial surfaces with -ribbon-constrained. Labels use categorical mapping; scalar maps use ribbon weights normalized by mapped valid-surface coverage, so a constant probability remains constant within covered cortex. Original CIFTI volume components are resampled onto the requested grid and take precedence at overlap. Coverage NIfTIs distinguish unmapped voxels (0), cortical ribbon (1), and original volume targets (2). JSON sidecars preserve map names, label tables, and methods. All surfaces, the reference, and CIFTI volume must already share physical space; this exporter does not register between native and MNI spaces.

Current subcortical regression derives neighborhoods from zero-based CIFTI voxels and subject surfaces, avoiding legacy distance matrices with a one-voxel origin shift. The historical rounded-distance boundary is preserved as physical distance strictly below distance_mm + 0.5. When aligned session/run metadata is available, regression fits each run separately. The default censored input uses retained frames for fitting. Updating code does not correct already regressed derivatives; regenerate from pre-regression data or use checked corrected inputs.

RidgePFM is the current name for the method previously called Ridge-Fusion. New runs use PFM_STRATEGY="ridgepfm", the PFM/RidgePFM/ folder, and RidgePFM_* filenames. The strategy aliases ridge_fusion, RidgeFusion, and ridge-fusion remain accepted; explicit PFM_RF_* settings still take precedence. Existing result folders are not moved or renamed. The default FC weight is 1.0 and the default spatial-prior weight is 0.05.

Enable with:

PFM_ENABLE=1
PFM_STRATEGY="ridgepfm"

RidgePFM estimates network assignments from a regularized fusion of subject functional connectivity evidence and spatial/network priors. The design goal is to provide a faster, prior-guided PFM path that remains sensitive to subject-specific deviations.

Open RidgePFM_VTX.dlabel.nii in Connectome Workbench with the subject surfaces. Template-fit R2, spatial-prior availability, and normalized fused-score weights are separate supporting layers. Fused-score softmax values rank competing labels but are not calibrated probabilities of true network identity or temporal stability. With PFM_RF_REPEAT_SUPPORT_ENABLE=1 and at least two runs retaining PFM_RF_REPEAT_MIN_FRAMES frames, RidgePFM also maps each run independently and averages their categorical assignments. The full concatenated map remains the primary estimate. ScanRepeatSupport distinguishes support for that primary label, competing-label frequency, modal-label support, unavailable-run frequency, available-run count, and normalized label entropy. ScanRepeatNetworkFrequencies contains the conditional frequency of every network among available runs. These are observed temporal repeat frequencies, not probabilities of biological membership, simultaneous membership, or a calibrated forecast for a future scan. With fewer than two eligible runs, status.json records not_estimable and no confidence map is invented.

Areal Parcellation

The network-map selector includes an Areal parcellation checkbox. Each example taxonomy has its own FC-derived parcels, computed downstream of its vertex-wise WTA map with the existing areal stage (including its WTA cleanup). The toggle loads those precomputed results; it does not estimate new parcels in the browser. WTA fills summarize the surface-area-weighted majority network identity within each parcel; softmax fills show its surface-area-weighted mean network support. Selecting a different softmax network retains that taxonomy’s parcel geometry. These parcel summaries are not a second RidgePFM fit or calibrated identity probabilities.

Enable with:

PFM_AREAL_ENABLE=1

Areal parcellation sub-parcellates the network-level map into smaller areal parcels. The output name is derived from the network-label prefix unless overridden:

PFM/RidgePFM/RidgePFM_VTX+ArealParcellation.dlabel.nii
PFM/Infomap/InfomapNetworkLabels+ArealParcellation.dlabel.nii

Controls:

PFM_AREAL_MIN_SIZE=30
PFM_AREAL_OUTFILE=""

Experimental Multi-Network RidgePFM Maps

The opt-in multi-network extension asks whether a fixed RidgePFM parcel is described better by two or three network FC templates than by its WTA network alone. Enable it only with RidgePFM areal parcellation:

PFM_STRATEGY="ridgepfm"
PFM_AREAL_ENABLE=1
PFM_RF_MULTINETWORK_EXPERIMENTAL_ENABLE=1

Preliminary internal evaluations are encouraging, but the method still needs broader testing across participants and acquisition conditions. It therefore remains disabled by default and should currently be interpreted as an experimental descriptive layer.

The experiment randomly distributes contiguous 25-frame blocks from every scan across thirds, selects a convex one-, two-, or three-network description on two thirds, and scores it on the held-out third. The default eight repeats produce 24 held-out folds. Added networks must recur in at least 80% of folds, improve held-out fit in at least 80%, have positive mean gain in every split repeat, and carry a nontrivial mixture weight (defaults: 0.20 for the second network and 0.15 for the third).

The default parcelwise null preserves each parcel's complete held-out gain landscape but permutes the correspondence between the added-network identity selected on training data and its held-out identity. Thus generic improvement from simply adding model flexibility is included in the null. Two thousand repeat-preserving permutations yield parcelwise p-values, followed by Benjamini-Hochberg FDR at 0.05 separately in cortex and subcortex. Three-network support must pass both sequential comparisons (2 vs 1 and 3 vs 2). The older whole-brain max-statistic result is retained in the CSV and dscalar as a separate extreme-confidence FWER tier.

This layer keeps the full-data parcel geometry fixed and does not rerun areal parcellation or RidgePFM within each fold. It is a held-out FC-template mixture diagnostic, so it supplements rather than replaces the original WTA and probability maps.

The parcel dlabel stripes every null-selected parcel that also meets the configured cortical/subcortical parcel-size requirement. The localized dlabel is more conservative spatially: within a selected parcel, it requires the same network set to have local RidgePFM support and form a minimum-size contiguous surface or volume cluster. Thus a parcel may be striped in the parcel map but remain WTA in the localized map when its evidence is diffuse. This is a parcel-anchored vertex/voxel translation, not a separate vertexwise CV/null refit. Outside retained local clusters it exactly preserves the original RidgePFM vertex/voxel WTA labels. The 0.10 local cutoff is twice the uniform 1/20 reference probability; it is an effect-size screen, not a calibrated posterior-probability threshold.

The candidate-identity null is conditional on the observed candidate-gain landscape; it is not a generative residual surrogate under a fitted one-network timeseries model. Treat this as an experimental descriptive layer until it replicates across subjects and a full residual-surrogate or per-fold RidgePFM analysis confirms calibration.

Workbench Review Checklist

For each subject:

  • Open the subject midthickness/inflated surfaces.
  • Load the network dlabel, borders, R2/probability maps, and homogeneity figure.
  • Check whether maps respect expected sensory/motor/association topography.
  • Check for session-specific artifacts using QC reports before interpreting unusual network deviations.
  • Compare RidgePFM and Infomap when both were run.
  • Record any manual Infomap corrections in the per-density correction tables.
